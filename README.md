# 건축BIM섹션 주간 업무현황 대쉬보드

`dashboard.html` 을 더블클릭하면 열립니다 (Chrome / Edge 권장). 인터넷 연결 없이 동작하며, 지도 타일(OpenStreetMap)만 외부에서 불러옵니다.

## 폴더 구성
```
BIM_Dashboard/
├─ dashboard.html            대쉬보드 본체
├─ build_dashboard.py        Excel → data/data.js 변환 (취합 담당자용, Python 3 + openpyxl)
├─ data/
│   ├─ 주간업무현황_템플릿.xlsx          담당자 배포용 빈 템플릿
│   ├─ 주간업무현황_2026-08-31_샘플.xlsx  샘플 데이터
│   └─ data.js                          대쉬보드가 읽는 데이터 (build_dashboard.py 생성)
├─ ifc/                      (선택) 웹서버 배포 시 IFC 보관 폴더 – 평소에는 프로젝트별 IFC경로 사용
└─ lib/                      라이브러리 (Chart.js, SheetJS, Leaflet, three.js, web-ifc) – 수정 불필요
```

## 주간 운영 흐름
1. **배포** – `data/주간업무현황_템플릿.xlsx` 를 담당자에게 배포 (또는 지난주 파일을 이어서 사용). 엑셀 대신 대쉬보드 화면에서 바로 입력해도 됩니다 (아래 "화면에서 직접 입력" 참고)
2. **작성** – 담당자는 `업무현황`(본인 업무, 매주 새 행) · `인력현황`(본인 1행) 작성. 새 프로젝트/과제는 `프로젝트개요` 에 행 추가
3. **취합/반영** – 세 가지 방법 중 선택
   - **A. Excel 파일 연결(권장)**: 상단 `Excel 파일 연결` 로 취합 xlsx(여러 개 가능)를 한 번 선택 → 즉시 반영되고, 이후 **Excel에서 저장할 때마다 3초 이내 자동 반영**(브라우저가 파일을 기억. 다음에 열 때 `Excel 재연결` 한 번 클릭). Chrome/Edge 필요
   - **B. 드래그**: xlsx 파일을 화면에 드래그 → 즉시 반영(자동 갱신 없음, 본인 브라우저에 저장). `data.js로 초기화` 로 되돌림 (2026-09: 한 번만 불러오는 `불러오기` 버튼은 툴바에서 제거되었고, 드래그로만 이 방식을 사용합니다 — Excel 파일 연결과 기능이 겹쳐 정리했습니다)
   - **C. data.js 갱신(전 직원 공유용)**: xlsx 를 `data/` 에 넣고 `python build_dashboard.py` → `data/data.js` 갱신 → HTML을 여는 모든 직원에게 반영
   - 시트는 **헤더 이름으로 인식**하므로 열 순서가 달라도 되고, 이전 양식(담당자(E&C)/담당(A&C)/비고)도 그대로 읽힙니다. 구분이 비어 있으면 PJT지원, ID가 `-`이면 프로젝트명이 ID로 사용됩니다.
4. **주차 선택** – 상단 `기준 주차` 로 과거 주차 상태 조회. 추이 그래프는 전체 주차 표시

## 화면에서 직접 입력 (엑셀 없이)

- 화면 순서(2026-09 변경): ① 업무현황 ② 인력현황(근태) 가 위에 바로 보이고, **③ 프로젝트개요 · ④ 인원(기본 명단)은 평소엔 접혀 있다가** 제목을 클릭하면 펼쳐져서 수정할 수 있습니다 (신규 등록·정보 수정이 필요할 때만 펼치면 됨).
- 각 칸을 고치고 다른 곳을 클릭(포커스 아웃)하면 대쉬보드 전체·이 브라우저(localStorage)에 즉시 반영됩니다. 새로고침해도 유지됩니다.
- 행 삭제는 각 행 끝의 `✕`.
- **인력현황(근태)** 칸에는 출장/야근/주말근무/연차/반차 중 해당 사항을 쉼표로 입력합니다 (예: `출장,야근`). 비우면 없음.
- 상단 `엑셀로 내보내기` 버튼을 누르면 지금까지 화면에 입력·수정한 내용을 **기존 시트 구조 그대로**(프로젝트개요/업무현황/인원/인력현황) xlsx로 저장합니다. 이 파일은 지금 쓰시는 취합 방식(Excel 파일 연결 / 불러오기 / `build_dashboard.py`)에 그대로 이어서 쓰면 됩니다 — 즉, "화면 직접 입력"은 엑셀 작성을 대신하는 또 하나의 입력 경로일 뿐, 취합·공유 방식은 바뀌지 않습니다.

- 새 프로젝트 ID는 업무현황과 서로 연결되는 값이니, 기존 프로젝트의 ID는 되도록 바꾸지 않는 것이 안전합니다.

(2026-09 변경) **이 ④ 간트는 이제 모든 프로젝트 블록이 같은 월/주 시간축을 공유** — 위아래로 스크롤해도 같은 날짜는 모든 블록에서 같은 x좌표에 오도록 정렬되어(오늘 점선도 모든 블록에서 같은 위치), 프로젝트끼리 일정을 바로 비교할 수 있습니다. 수행과제·기타업무 탭의 간트도 동일합니다.

  - (2026-09 개선) **주차별 요일 근태 현황표에 월 선택이 추가**되었습니다. 이전에는 데이터가 쌓인 모든 주차를 한 표에 옆으로 계속 늘어놓아 데이터가 많아질수록 표가 한없이 넓어졌는데, 이제 표 제목 옆 월 선택에서 고른 **그 달에 해당하는 주차만** 표시됩니다 (기본값은 데이터가 있는 가장 최근 달).

## NAS/웹 미리보기에서 열 때 오류가 나는 경우
- `mcas-proxyweb.mcas.ms/js-bootstrap.js … about:srcdoc` 오류는 NAS 웹 미리보기가 HTML을 iframe(srcdoc) 안에 넣어 보여줄 때 회사 보안 프록시(Microsoft Defender for Cloud Apps)가 삽입한 스크립트가 실행되지 못해 나는 메시지입니다(대쉬보드 코드 오류 아님). 이 상태에서는 lib/·data/ 상대경로와 파일 접근도 막힙니다.
- 해결: ① 탐색기에서 네트워크 드라이브의 `dashboard.html` 을 직접 더블클릭(권장, 바로가기 배포) ② NAS Web Station 등 웹서버로 폴더를 서비스해 `http://nas/…/dashboard.html` 로 접속 ③ 미리보기로만 공유해야 하면 `python build_single.py` 로 만든 **dashboard_single.html**(라이브러리·데이터 내장) 사용
  - (참고) `build_single.py`에 `xlsx.full.min.js` 라이브러리 자체 코드 안의 문자열 `</body>` 때문에 IFC 라이브러리가 파일에 중복 삽입되어 dashboard_single.html이 깨지는 문제가 있었습니다 – 이번에 수정했습니다(정상 크기 약 9MB). `data/data.js`를 갱신했다면 `python build_single.py`를 다시 실행해 최신 내용으로 재생성하세요.

### dashboard_single.html 을 외부/타인에게 "따로" 보낼 때 (2026-09 개선)
- `dashboard_single.html` 은 만드는 **그 순간의 데이터를 통째로 담아 굳혀놓은 스냅샷**입니다. 만든 뒤에 데이터가 더 갱신돼도 이미 만들어둔 예전 파일 자체에는 자동으로 반영되지 않습니다 — 새로 만들어(재생성해) 보내야 최신 정보가 담깁니다.
- **파이썬 스크립트(`build_dashboard.py`/`build_single.py`)로 만드는 방법**: `python build_dashboard.py`(엑셀 → data.js 갱신)를 실행하면 그 끝에서 `dashboard_single.html`도 자동으로 함께 재생성됩니다. 단, 이 방법은 **`data/data.js` 파일에 실제로 반영된 내용만** 담습니다 — `데이터 입력` 탭에서 화면에 입력만 하고 아직 `엑셀로 내보내기` → 취합을 거치지 않은 내용(그 브라우저의 localStorage에만 있는 내용)은 여기 포함되지 않습니다.
- **화면에서 바로 만드는 방법(신규, 파이썬 불필요)**: 상단 `공유용 단일파일 다운로드` 버튼을 누르면 **지금 이 화면에 실제로 보이는 데이터**(방금 입력·수정해서 아직 취합 전인 내용까지 포함) 그대로, `데이터 입력` 탭만 뺀 하나의 HTML 파일을 그 자리에서 만들어 다운로드합니다. "예전 정보가 담긴 파일을 보내게 되는" 문제의 근본 원인이 대부분 여기(화면에는 최신인데 취합/재생성을 안 거친 채 예전 dashboard_single.html을 그대로 보냄)였기 때문에, 공유 직전에 이 버튼을 누르는 것이 가장 확실합니다.
  - **탐색기에서 파일을 직접 더블클릭해서 연 경우(`file://`)에도 동작합니다** (NAS Web Station 등 웹서버 설정 불필요):
    - 지금 열려 있는 파일이 **이미 `dashboard_single.html`(단일 파일)이면** — 라이브러리가 이미 다 들어있으므로 버튼을 누르면 별다른 창 없이 바로 최신 데이터로 다시 만들어 다운로드됩니다. (가장 흔히 쓰게 될 경우 — 늘 갖고 있는 단일 파일을 열어서 최신 상태로 갱신 후 재공유)
    - 지금 열려 있는 파일이 **`dashboard.html`(라이브러리가 아직 lib 폴더에 따로 있는 다중 파일 버전)이면** — 브라우저가 file://끼리는 자동으로 파일을 읽어올 수 없어서, 버튼을 누르면 이 dashboard.html이 들어있는 폴더(`lib` 폴더가 함께 있는 폴더, 보통 `BIM_Dashboard` 폴더 자체)를 선택하는 창이 뜹니다. **처음 한 번만** 선택하면 브라우저가 그 폴더를 기억해두고, 다음부터는 버튼을 눌러도 **폴더 선택 창 없이 바로** 최신 데이터로 다시 만들어 다운로드됩니다("파일 지정…"으로 IFC를 프로젝트별로 기억해두는 것과 같은 방식) — 완전한 자동 지정은 브라우저 보안정책상 불가능하지만, 첫 선택 이후로는 사실상 자동입니다. (2026-09 수정: 이전 버전은 폴더 선택 전에 안내 팝업(alert)이 먼저 떴는데, 그 팝업을 읽는 동안 시간이 지나면 브라우저가 "방금 누른 버튼 클릭"으로 인정해주는 유효시간이 끝나버려 정작 폴더 선택 창 자체가 뜨지 않는 문제가 있었습니다 — 안내 팝업을 없애고 버튼을 누르자마자 바로 폴더 선택 창이 뜨도록 고쳤습니다.)
  - 웹서버(`http://`, 예: NAS Web Station)로 열었다면 폴더 선택 없이 자동으로 lib을 읽어와 더 매끄럽게 동작합니다.
- **`dashboard_single.html`은 조회 전용입니다 — `데이터 입력` 탭이 자동으로 빠져 있습니다.** 데이터 편집은 `dashboard.html`(다중 파일 버전)에서만 하고, 외부 공유용으로 내보낼 때만 위 두 방법 중 하나로 `dashboard_single.html`을 만드세요. (dashboard.html 쪽 코드는 이 탭이 없어도 다른 기능이 깨지지 않도록 안전장치가 되어 있습니다.)
